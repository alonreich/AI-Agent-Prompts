PHASE 1: AUDIT (STATIC SOURCE + RUNNING APP)
Audit both source code (tracing shared components, inherited styles, and handlers) and the live running app (using disposable data/accounts). Report only issues with real user impact:
1. FLOW & GUIDANCE: Unclear first-run/next steps, dead ends, missing Back/Cancel, missing empty states, confusing multi-step flows, poor navigation. Require onboarding/tooltips only when solving a real need.
2. FEEDBACK & LONG OPS: Missing/misleading progress, unexplained waits, no safe cancel, missing success/output-location confirmation, UI freezes, silent failures. Never require an invented ETA when unreliable.
3. ERRORS & SAFETY: Raw exceptions/codes, actionable recovery missing, missing validation, destructive actions without confirmation/undo, data loss, placeholders used instead of persistent labels.
4. MICROCOPY & I18N: Jargon, inconsistent terminology, vague action labels, hardcoded non-localizable strings, text truncation, incomprehensible runtime messages.
5. VISUAL HIERARCHY: Unclear primary/secondary actions, ungrouped/unlabeled controls, information overload, inconsistent spacing/typography/icons/alignment against the established design system.
6. DESIGN SYSTEM: Unjustified hardcoded colors/sizes/fonts, conflicting styles, broken theme inheritance, broken dark/light/high-contrast modes.
7. ACCESSIBILITY (WCAG 2.2 A/AA & Platform Conventions): Accessible names/roles/states/labels/headings, full keyboard/switch access, focus order/visibility, focus trapped/returned in modals, focus not obscured by overlays, live error/status announcements, color-independent meaning, contrast (4.5:1 normal text, 3:1 large text/non-text UI), pointer/touch targets (minimum 24x24 CSS px or platform guideline), alt text, captions, paste/password-manager support, drag alternatives, 200% zoom/reflow, reduced motion (usability check, not an automatic AA failure alone).
8. INTERACTION STATES: Missing/confusing hover, pressed, focus, disabled (with clear reason), selected, error, and loading states. Follow platform conventions (missing hand cursor is not a defect on native desktop/mobile).
9. LAYOUT & RESPONSIVENESS: Overflow, clipped/obscured controls, DPI/text scaling breaks, mobile keyboard obstruction, orientation issues, long-string/RTL breakage. Report fixed sizes/negative margins only if causing visible bugs.
10. OVERLAYS: Z-index/stacking conflicts, stacked modals, backdrop issues. Esc/outside-click/back-gesture dismissal must protect unsaved work.
11. PERCEIVED PERFORMANCE: Slow startup/interactions, UI-thread blocking, excessive re-renders, unvirtualized large lists, heavy assets, laggy previews/exports. Code patterns alone are not proof—measure or mark Confidence: Not verified.
12. STATE & PERSISTENCE: Stale UI after state updates, lost drafts/selections/preferences/window states/last-used paths. Accept the framework's idiomatic state pattern.
13. NETWORK & IDEMPOTENCY: Offline/timeout/partial-failure handling, retry/cancel paths, preserving user input. Repeated clicks/retries/refreshes must not duplicate saves, submissions, jobs, or exports. Distinguish failed requests from lost responses.
14. AUTH, SESSIONS & PRIVACY: Session expiry during active work/long ops, recovery after re-auth, revoked OS/app permissions, role changes, sensitive data leaked in UI/logs/history/cache after logout.
15. CONCURRENCY (MULTI-TAB / WINDOW / INSTANCE): Test second tab/window (web) or second instance (desktop/mobile) on the same workspace/output target. Verify no silent overwrites, data resets, duplicate jobs, or file corruption; verify locks/conflicts or sync/isolation work as intended and stale locks recover safely.
16. BLOAT, CLUTTER & INTERACTION COST: Excessive clicks/steps for common actions (reduce 3+ clicks to 1–2 clicks, direct buttons, or shortcuts/context menus); bloated settings screens with too many visible options; wordy descriptions or long labels that should be compressed into 2–4 words (e.g., "Change brightness") or moved into tooltips/collapsible sections.

EVIDENCE, CONFIDENCE & SEVERITY RULES
- One root cause = one merged issue. Cite exact relative paths and line ranges (e.g., src/views/Main.tsx:14-29). If observed only at runtime, write "Source not located" and provide reproduction steps. Never invent paths or results.
- Confidence: Confirmed (proven by code or observed at runtime), Likely (code evidence exists, runtime check needed; use "may" in CURRENT ISSUE and state missing check in TECHNICAL), Not verified (check blocked; coverage gap, not a defect).
- Severity: Critical (blocks core task, data loss, crash, blocks accessibility), High (major recurring confusion/failed work), Medium (noticeable usability/consistency issue), Low (minor polish).
- Incomplete coverage: If required checks could not run, add at most ONE final item: TITLE: Review incomplete, Severity: Low, stating "Coverage limitation, not a confirmed defect" and listing untested checks in TECHNICAL with Confidence: Not verified.
- Zero defects found: If review is complete with no issues, output ONE item with RANK: 0 | Low, TITLE: No confirmed issues found, scoped summary in CURRENT ISSUE, verified checks in EXPECTED BEHAVIOR, and scope evidence in TECHNICAL.
