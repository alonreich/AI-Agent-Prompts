# AUDIT CHECKLIST (WHAT YOU MUST INSPECT IN THE CODEBASE)
Scrape and trace all UI files, state/configuration files, backend handlers, storage mechanisms, and layout definitions against these 19 criteria:

1. **Functional Wiring & Save Persistence (HIGHEST PRIORITY):** Trace every setting from the UI control -> through the Save/Apply trigger -> into storage/config -> to the actual application logic that uses it. Identify any setting that fails to save, resets unexpectedly, is ignored by the app, or is not wired to its underlying function ("dead" or placebo settings).
2. **Information Architecture & Grouping:** Identify settings scattered across too many tabs or groups that should be consolidated into fewer, logical, top-tier application groupings.
3. **Visual Priority (Top-to-Bottom Order):** Ensure the most important, frequently used settings sit at the very top of each tab, and advanced/least-used settings sit at the bottom.
4. **Microcopy Simplification:** Identify vague, wordy, or overly technical setting labels, checkboxes, and menus that should be rewritten into ultra-short, catchy, native human phrases.
5. **Tooltips (`i` / `?` Icons):** Check every setting for a hover/click tooltip. Flag missing or technical tooltips. Every tooltip must provide a verbose, detailed, yet oversimplified non-technical explanation so an average user immediately understands what the setting does.
6. **Setting Logic & UI Control Selection:** Evaluate whether the UI control matches the setting's logic (e.g., replacing an awkward spinning dial or raw text box with a slider, radio dots, toggle switch, dropdown, stepper, or a file path input with a `"Browse..."` button).
7. **UI Layout, Sizing & Visual QA:** Check for input boxes/dropdowns that are too wide or too narrow for their values, wasted horizontal/vertical screen space, cut-off/truncated text, overlapping objects, or poorly aligned buttons.
8. **Window State & Memory:** Check if the settings window can be moved and resized, and whether it remembers its last size, screen position, and last active tab when reopened.
9. **Conditional Dependencies:** Identify sub-settings that should be dynamically grayed out or hidden until their parent setting/toggle is enabled.
10. **Input Validation & Formatting:** Check for missing field limits (numeric-only, min/max ranges, valid URLs/paths) and missing inline error messages.
11. **Save, Apply & Restart Behavior:** Check for clear Save/Cancel vs. auto-save behavior, "unsaved changes" warnings when closing, and clear notices on settings that require an app restart.
12. **Restore Defaults:** Check for both per-tab/per-setting and global `"Restore Defaults"` buttons with confirmation prompts.
13. **Backup & Import Settings:** Check for one-click `"Backup Settings"` and `"Import Settings"` functionality.
14. **Danger Zone Isolation:** Ensure destructive actions (wipe data, revoke keys, factory reset) are isolated at the bottom in a red `"Danger Zone"` with confirmation dialogs.
15. **Search & Keyboard Navigation:** Check for an instant search bar (if >15 settings) and proper `Tab` focus order, `Esc` to close, and `Enter` to apply.
16. **Cutting Bloat & Redundancy:** Identify obsolete, redundant, or overly granular settings that regular users do not need, which should be deleted entirely, merged into a single unified control, or automated behind the scenes to make the settings menu shorter and cleaner.
17. **Security & Sensitive Data Protection:** Check whether passwords, API keys, tokens, or secrets are masked in the UI (`•••••` with a show/hide eye toggle), redacted from logs/exports, and encrypted or stored in a secure OS credential vault rather than saved in plain-text configuration files.
18. **Dark Mode, Theming & Accessibility:** Check dark/light/system theme contrast ratios, dynamic font/DPI scaling without layout breakage, colorblind-safe status indicators, screen-reader (ARIA/accessibility) labels, and visible keyboard focus rings.
19. **Window Z-Order, Focus Handoff & Modal Lifecycle:** Inspect how secondary menus, child dialogs, or external windows launch from the main application or from within Settings. Identify windows that spawn behind the active window (Z-order/topmost bugs), orphaned windows that remain open in the background instead of closing or properly handing off focus when jumping from Window A to Window B, missing modal parenting, or duplicate instances of the same window opening simultaneously.
