## UNIVERSAL SYSTEM AUDIT DOMAINS

### 1. Architectural Modernization & Runtime Efficiency
- Runtime & Execution Models: Evaluate language runtimes, interpreter bottlenecks, JIT vs. AOT compilation, native binary opportunities, and memory footprint.
- Framework & Paradigm Shifts: Identify opportunities to replace obsolete, high-overhead frameworks with decoupled, modern, high-throughput architectures suitable for the target platform.

### 2. Concurrency, Race Conditions & State Tearing
- Race Conditions: Detect Time-of-Check to Time-of-Use (TOCTOU) races where file existence, service readiness, or collection bounds are checked without continuous synchronization.
- Out-of-Order Execution: Verify whether asynchronous operations can resolve out of sequence during rapid user input, polling, or filtering, overwriting current application state.
- Unsynchronized Access: Flag shared mutable state accessed concurrently across threads, goroutines, or async event loops without proper atomics, mutexes, or immutable snapshots.
- Contention & Event Loop Blocking: Flag blocking synchronous system calls, heavy compute, or disk/network I/O executing on main threads, UI threads, or single-threaded event loops (e.g., Node/Python/Electron).
- Queue & Pipeline Topologies: Verify intensive workloads (parsing, hashing, compression, heavy compute) execute on decoupled worker pools via non-blocking channels or message queues.

### 3. Defensive Storage, Path Handling & Crash Persistence
- Storage Fragility: Audit persistence logic to ensure paths, buckets, and directories are never presumed to exist. Verify input sanitization, path length handling, illegal characters, and directory traversal protections.
- Atomic Persistence: Flag direct writes to target data files. Enforce atomic patterns (write to unique temp file -> sync/flush to disk -> atomic rename/swap). Ensure serialization offloads from critical loops.
- IPC vs. Disk Serialization: Flag transitions serializing state to disk files purely to pass data between processes or components. Enforce high-throughput shared memory, pipes, or domain sockets.

### 4. Pipeline Performance, Resource Management & High-Throughput Buffering
- Zero-Copy & Allocation Invariants: Trace data flow across boundary layers. Flag redundant buffer allocations, deep object clones, and repeated serialization round-trips.
- Resource Starvation & Drift: Ensure balanced compute distribution across CPU/GPU cores. Ensure multi-source data streams sync to an authoritative clock to eliminate phase jitter and drift.

### 5. Data Validation, State Integrity & Serialization Safety
- Schema & Boundary Integrity: Audit data ingestion for schema validation, type parsing boundaries, and payload limits to reject malformed inputs early.
- Numerical Safety: Check for precision loss, overflow/underflow, floating-point rounding errors, and unhandled edge values (NaN/Infinity).

### 6. Real-Time Constraints, Event Loops & Non-Blocking Execution
- Critical Loop Safety: In tight loops or real-time threads (render cycles, audio callbacks, streaming pipelines), flag dynamic allocations, runtime garbage collection spikes, lock contention, or blocking syscalls.
- Lock-Free Mechanics: Enforce ring buffers, object pools, or atomic queues for producer-consumer workflows on hot paths.

### 7. Caching Strategies, Memory Bounds & Eviction Topologies
- Access Patterns: Audit caching logic for memory bloat, partial hydration, and redundant lookups.
- Bounds & Eviction: Enforce strict capacity limits and deterministic eviction policies (LRU/TTL) on all caches and in-memory stores to prevent memory leaks and out-of-memory crashes.

### 8. Unmanaged Resources, Memory Safety & Lifecycle Ownership
- Resource Lifecycle: Audit pointers, foreign function interfaces (FFI), native OS handles, database connections, and file descriptors. Enforce strict RAII, context managers, or explicit lifecycle disposal.
- Reflection & Dynamic Loading: Flag fragile runtime introspection, dynamic code evaluation, or un-annotated metadata that degrades compiler optimizations, tree-shaking, or binary shrinking.

### 9. Monoliths, God Classes & Structural Decoupling
- God Files, Massive Classes & Bloated Models: Identify oversized files, god classes, giant UI modals, or bloated data models that bundle multiple responsibilities into fragile single points of failure. Flag tightly coupled logic where modifying one feature risks breaking another.
- Modular Compartmentalization: Deconstruct monolithic entities into small, isolated, single-responsibility services, sub-modules, and bounded state containers to maximize stability, eliminate ripple-effect regressions, and boost execution performance.
- Logic Consolidation: Locate duplicate math, parsing, state transforms, or validation routines across modules and extract them into pure, reusable domain utilities.


### 10. Logging Pipeline Health & Silent Error Swallowing
- Silent Failures: Flag generic or empty catch/except blocks hiding fatal faults, connection drops, or resource exhaustion.
- Bounded Logging: Enforce asynchronous, non-blocking logging with file rotation and size caps to prevent disk exhaustion and thread blocking.

### 11. Client/UI Lifecycle, State Management & Event Routing
- Render & State Thrashing: Detect recursive updates, invalidation loops, and memory-retaining event listeners.
- Input Scoping: Ensure user shortcuts and global input events route through a centralized manager that correctly scopes focus contexts.
